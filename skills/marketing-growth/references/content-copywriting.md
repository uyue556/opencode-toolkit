## 1. Copywriting

Operating mode: **conversion copywriter, not brand poet.** Clarity beats cleverness; outcomes beat features; specificity beats buzzwords; honesty beats hype. You may **not** fabricate claims, statistics, testimonials, or guarantees.

### Phase 1 — Context (mandatory, ask if missing)
1. **Page purpose:** page type + ONE primary CTA (+ optional secondary).
2. **Audience:** role, problem, what they tried, objections, their language.
3. **Product/offer:** what's offered, differentiator, primary outcome, available proof.
4. **Context:** traffic source, awareness level (unaware → problem-aware → solution-aware → product-aware).

### Phase 2 — Copy Brief Lock (hard gate)
Before writing, present a 4–6 bullet brief (goal, audience, core value prop, primary CTA, traffic/awareness) plus explicit assumptions, then ask: *"Does this copy brief accurately reflect what we're trying to achieve?"* **Do not proceed until confirmed.**

### Phase 3 — Principles
- Clarity over cleverness; benefits over features; specificity over vagueness; customer language over company language; one idea per section.
- Always connect: **Feature → Benefit → Outcome.**

### Phase 4 — Page structure
- **Above the fold:** outcome-focused headline, 1–2 sentence subheadline, action-oriented primary CTA.
- **Core sections (as appropriate):** social proof → problem/pain → solution & 3–5 benefits → how it works (3–4 steps) → objection handling (FAQ/comparison/guarantee) → final CTA with risk reduction.

### Phase 5 — Deliverables
- Section-labeled page copy; 2–3 headline and CTA alternatives **with rationale**; annotations on key sections (why this, which principle, what alternatives).

### Claim discipline
No fabricated data/testimonials · no implied guarantees · no exaggerated speed/certainty · mark missing proof as placeholders.

## 2. Copy Editing (Seven Sweeps)

Editing enhances, doesn't rewrite. Run **seven sequential passes**, each on one dimension, looping back to verify earlier sweeps. One unfocused pass misses everything; multiple focused passes catch it.

| Sweep | Focus | Key question |
|---|---|---|
| 1 Clarity | Understandability | Can the reader understand this? |
| 2 Voice & Tone | Consistency | Does it sound consistent? |
| 3 So What | Benefit bridge | For every claim: "okay, so what?" |
| 4 Prove It | Evidence | Is every claim supported? |
| 5 Specificity | Concreteness | Can this be more specific? |
| 6 Heightened Emotion | Feeling | Does it make the reader feel something? |
| 7 Zero Risk | Friction removal | What would make someone hesitate? |

### High-value moves
- **So What:** "Our platform uses AI-powered analytics" → add "…so you can make better decisions in half the time."
- **Prove It:** "Trusted by thousands" → name who, how many, with specifics.
- **Specificity upgrades:** "Save time" → "Save 4 hours every week"; "Many customers" → "2,847 teams"; "Fast results" → "Results in 14 days."
- **Heighten emotion:** paint the before-state vividly, use sensory language, tell micro-stories, ask reflective questions. Emotion must serve the message, never manipulate.
- **Zero Risk:** near-CTAs add money-back guarantee, "No credit card required", "Cancel anytime", social proof, clear next-step expectations.

### Word-level cuts
Very/really/extremely/incredibly · just/actually/basically · in order to (→ to) · that (often) · things/stuff.
Weak → strong: utilize→use, implement→set up, leverage→use, facilitate→help, innovative→new, robust→strong, seamless→smooth, cutting-edge→new.

### Sentence/paragraph rules
One idea per sentence · vary length (mix 3-word and 25-word sentences) · front-load important info · max ~25 words per sentence · short paragraphs (2–4 sentences for web) · strong openings · white space.

### Common problems
| Problem | Fix |
|---|---|
| Wall of features | Add "which means…" after each feature |
| Corporate speak | "How would a human say this?" |
| Weak opening | Lead with reader's problem/outcome |
| Buried CTA | Make it obvious, early, repeated |
| No proof | Specific testimonials, numbers, cases |
| Generic claims | Specify who, how, by how much |
| Mixed audiences | Pick one audience, write directly to them |
| Feature overload | Focus on 3–5 benefits that matter most |

## 3. Brand Voice & Guidelines

### Establishing a voice (first-time setup)
1. Analyze existing content to establish a baseline.
2. Define voice attributes: pick a primary archetype + 3–5 tone attributes.
3. Write 3 sample pieces in that voice and test consistency.
4. Document and apply consistently across all content.

### A pragmatic tone model (from brand-guidelines)
Choose tone by context:
| Plain Speech (default) | Personality voice |
|---|---|
| UI buttons/labels, docs, error messages, settings, transactional email, help text | 404 pages, empty states, onboarding, loading states, announcements, marketing copy |

**Plain Speech rules:** concise; direct ("Save" not "You can save"); active voice; no jargon; specific ("3 errors found" not "Some errors found").
**Personality rules:** empathetic, self-aware, fun but functional; earned moments only. **Never** use personality in error messages, settings, docs, or billing (users are frustrated or need trust).
**General:** American English; Title Case headings, Sentence case buttons/labels; no exclamation marks in UI; no periods in button labels; no ALL CAPS except acronyms.
**Error messages:** say what happened → why (if helpful) → what to do next. "Could not save changes. Check your connection and try again."

## 4. Keyword Extraction

Extract up to 50 SEO keywords from text, output as a **single comma-separated lowercase line**, ordered by relevance, no duplicates/near-duplicates, mix of single words and 2–4 word phrases, no numbering/bullets.

### Quality rules
- Prefer noun phrases over verbs/adjectives; prioritize domain terminology, meaningful nouns, search phrases, entities, technical concepts.
- **Each keyword must be something a user would type into a search engine.**
- Avoid vague fillers ("important methods", "various techniques", "things").

### Workflow
Analyze (subject/topics/entities) → Generate (≤50, ≤4 words) → Rank (main topic first, then high-value terminology, tools/entities, common queries, supporting topics) → Normalize (lowercase, dedupe, keep most common phrasing) → Validate (count ≤50, no dupes, no trailing period). For very short text, infer likely topics.

## 5. SEO-Optimized Blog Content

### Research
- Primary keyword (aim search volume ~500–5,000/mo), 3–5 secondary keywords, 10–15 related/LSI terms.

### Structure
- Keyword in title, first paragraph, and 2–3 H2s; 1,500–2,500 words for comprehensive coverage; answer the question in the opening paragraph.

### On-page checks
- Keyword density ~1–3%; proper heading hierarchy (one H1, logical H2/H3); internal + external links; optimized meta description; author byline + dates; `datePublished`/`dateModified` schema.

### Production process
Start with audience need → research before writing → outline → first draft without editing → optimize for SEO → edit for brand voice → proofread and fact-check → optimize for platform → schedule.

### Quality indicators
SEO score >75/100; readable for the audience; consistent voice; clear value proposition; actionable takeaways; platform-optimized; CTA present; proofread.
